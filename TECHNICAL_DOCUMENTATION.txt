PURPOSE
Static personal brand website for https://j3d1.fm.

STACK
- Next.js 16 static export
- React 19
- Node.js 24-25 build runtime
- CSS-only responsive visual system and signal animation
- GitHub Pages hosting

STRUCTURE
- app/page.tsx: page content and semantic structure
- app/globals.css: complete visual system and responsive behavior
- app/layout.tsx: metadata, canonical URL and social cards
- public/og.png: social preview image
- public/CNAME: custom domain declaration
- .github/workflows/deploy.yml: production deployment
- tests/site.test.mjs: exported-site acceptance checks

LOCAL VALIDATION
Run npm test and npm run check. The first command builds the static export and
verifies the finished HTML, brand copy, absence of a personal name, custom
domain and social image. The second command validates the TypeScript source.

DEPLOYMENT
Pushes to main deploy the contents of out/ with the official GitHub Pages
workflow. Repository Pages settings must use GitHub Actions as the source.

DOMAIN
The apex domain j3d1.fm must point to GitHub Pages IP addresses. The repository
custom domain is j3d1.fm. HTTPS is enabled in GitHub after DNS verification.

CONTENT CONTRACT
Every product status on the page mirrors an entity card in the owner's
knowledge vault (wiki/articles/entities). Statuses are updated in the same
pass as the vault, never from memory. The page is pseudonymous: the export
test fails if the owner's personal name appears in out/index.html, and the
name must not appear in commits or metadata either. getdesign.net is not
linked until it serves real content.

SECURITY
The homepage remains static. /dzo-gtr/ contains a Google login interface only;
no report, PDF, warehouse credentials or financial rows may be committed here
or copied into public/ or out/. Firebase web configuration is public application
identification, not a server credential. Google tokens stay in browser memory.

PRIVATE FINANCE READER
- Frontend: app/dzo-gtr; Google sign-in through the existing Firebase project.
- Backend: services/finance-reader, Cloud Run dzo-gtr-finance-reader in europe-west1.
- Project: project-8d33c4d7-b3cc-40ac-a80.
- Firebase validates signature, audience, issuer and expiry; the API additionally
  requires Google provider, verified email and exact FINANCE_ALLOWED_EMAILS.
- Missing auth configuration or an auth emulator setting prevents startup.
- GET endpoints are authenticated; /v1/embed accepts an authenticated navigation
  POST that only reads the immutable HTML. No user write endpoints exist.
- GCS bucket is private with uniform access and public access prevention.
- Responses use no-store. No signed public object URLs are issued.
- The reader loads its immutable release from /v1/manifest, then pins dashboard
  and PDF requests to that release. Sign-out clears the frame and cancels reads.
- View sessions expire after 55 minutes; no financial data enters localStorage.
- Cloud administrators retain infrastructure permissions; viewer access is
  enforced by the application independently from infrastructure IAM.
- Reader deployment preserves its service account and production environment.
  Run: gcloud run deploy dzo-gtr-finance-reader --source services/finance-reader
  --region europe-west1 --project project-8d33c4d7-b3cc-40ac-a80
  --account j3d1fm@gmail.com. Never deploy an unauthenticated data handler.
- Reader tests: node --test services/finance-reader/tests/*.test.mjs.
- Roll back the service using its previous Cloud Run revision; roll back Pages
  with a Git revert. Financial release rollback switches the private current.json
  pointer to an earlier verified release; no financial files belong in this repo.

VERSION 0.3.1 — DOCUMENT NAVIGATION
The srcDoc reader caused History.pushState SecurityError when switching tabs.
The parent now POSTs id_token and the pinned release via a temporary hidden
form targeted at the iframe. /v1/embed requires the exact parent Origin, form
content type, one token and release field, at most 32768 actual body bytes,
and the same verified identity allowlist as the GET endpoints. CSP restricts
framing to the parent site. No bearer URL, cookie or public asset is introduced.
The frame runs on the API origin, isolated from the parent; logout and expiry
clear it. Reloading the parent signs in again; iframe GET alone is denied.
Protected Data runtime files and financial data are unchanged.
