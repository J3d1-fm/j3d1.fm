CONTENT CONTRACT
The public site names no projects or products. The home page is the brand
hero, the tuner dial and two profile links (GitHub, LinkedIn). The shared
description in app/layout.tsx and public/og.png stay equally neutral, because
/dzo-gtr/ inherits them for its link previews. The export test fails if a
known project name appears in any exported page or if the home page gains
another external link. The page is pseudonymous: the export test fails if the
owner's personal name appears in out/index.html, and the name must not appear
in commits or metadata either.

SOCIAL CARD
public/og.png is a 1200x630 render of tools/og.html, which loads the fonts
from app/fonts. Re-render it with headless Chrome from the repository root:
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
    --mute-audio --hide-scrollbars --force-device-scale-factor=1 \
    --window-size=1200,630 --virtual-time-budget=3000 \
    --user-data-dir="$(mktemp -d)" --screenshot="$PWD/public/og.png" \
    "file://$PWD/tools/og.html"
The separate profile keeps the render away from a running Chrome. tools/og.html
deliberately omits -webkit-font-smoothing so the type keeps the weight of the
earlier cards. Messengers cache link previews per URL; a changed card shows up
there only after their cache expires or is refreshed.

SECURITY
The homepage remains static. /dzo-gtr/ contains a Google login interface only;
no report, PDF, warehouse credentials or financial rows may be committed here
or copied into public/ or out/. Firebase web configuration is public application
identification, not a server credential. Firebase manages persisted authentication on the device; financial reports are not persisted by the application.

PRIVATE FINANCE READER
- Frontend: app/dzo-gtr; Google sign-in through the existing Firebase project.
- Backend: services/finance-reader, Cloud Run dzo-gtr-finance-reader in europe-west1.
- Project: project-8d33c4d7-b3cc-40ac-a80.
- Firebase validates signature, audience, issuer and expiry; the API additionally
  requires Google provider, verified email and exact FINANCE_ALLOWED_EMAILS.
- Missing auth configuration or an auth emulator setting prevents startup.
- GET endpoints are authenticated; /v1/embed accepts an authenticated navigation
  POST that only reads the immutable HTML. No user write endpoints exist.
- GCS bucket is private with uniform access and public access prevention.
- Responses use no-store. No signed public object URLs are issued.
- The reader loads its immutable release from /v1/manifest, then pins dashboard
  and PDF requests to that release. Sign-out clears the frame and cancels reads.
- View sessions last at most 30 days from Firebase signed auth_time. Firebase LOCAL persistence restores sign-in after reload/browser close; no report data is stored by the parent application.
- Cloud administrators retain infrastructure permissions; viewer access is
  enforced by the application independently from infrastructure IAM.
- Reader deployment preserves its service account and production environment.
  Run: gcloud run deploy dzo-gtr-finance-reader --source services/finance-reader
  --region europe-west1 --project project-8d33c4d7-b3cc-40ac-a80
  --account j3d1fm@gmail.com. Never deploy an unauthenticated data handler.
- Reader tests: node --test services/finance-reader/tests/*.test.mjs.
- Roll back the service using its previous Cloud Run revision; roll back Pages
  with a Git revert. Financial release rollback switches the private current.json
  pointer to an earlier verified release; no financial files belong in this repo.

VERSION 0.3.2 — REMEMBERED GOOGLE LOGIN
The previous inMemoryPersistence and 55-minute forced logout caused repeated
interactive sign-in. browserLocalPersistence now retains the Firebase session;
onIdTokenChanged restores the allowed user/report after reload and reacts to
sign-out in another tab. ID tokens retain Firebase's normal short lifetime and
getIdToken renews them before protected reads. Auth refresh does not reload the
existing report or discard its filters. No token is placed in a URL or log.

session.mjs is shared by frontend and reader. Its 30-day limit uses signed
auth_time rather than iat, so refresh cannot extend the interactive-login age.
The API enforces this on every data route; frontend checks while visible and
uses bounded daily timers to avoid 32-bit setTimeout overflow. Logout blanks the
iframe, aborts in-flight reads and calls Firebase signOut to remove persistence.
Transient load failures retain the authentication for retry; denied requests
clear it. Existing Google provider/email verification/exact allowlist remain.

The service Dockerfile and upload allowlists include only the shared policy
module and existing runtime inputs. No new dependencies, data files, roles,
viewers, schedules, cookies or infrastructure services are introduced.
Official contracts: https://firebase.google.com/docs/auth/web/auth-state-persistence
and https://firebase.google.com/docs/auth/admin/manage-sessions.
Local validation and deployment acceptance are appended below.
